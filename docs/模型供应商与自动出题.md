# 模型供应商与自动出题、分析

## 使用

1. 点击页面右上方「模型供应商」，新建一个模型连接。
2. 选择快捷配置，或直接输入 LiteLLM 供应商标识、模型 ID 和认证信息。可以保存多个连接，并设置默认连接。
3. 点击「保存连接」，再用「测试已保存连接」检查服务。测试只发送一条要求回复 OK 的短消息，供应商仍可能计费。
4. 打开已完成转写的课程，进入「让 AI 出题」，选择模型、题数和补充要求，点击「调用模型生成本课题集」。应用等待模型、验证题集协议并保存到本课，然后进入答题；参考答案默认隐藏。
5. 提交作答后进入「分析与复习」，选择分析模型和侧重点，点击「调用模型分析本课作答」。反馈会自动保存到本题集，并可继续编辑。

出题和分析可以使用不同连接或模型。手动复制资料、粘贴题集、粘贴反馈和导出作答的方式全部保留。

## 复用上游供应商适配

调用层直接使用 [LiteLLM 的 `acompletion`](https://docs.litellm.ai/docs/python_sdk)，本项目没有重新手写各家的 HTTP 请求协议或返回值适配器。当前安装的是官方轻量发行包 **`litellm-core==1.108.0`**，使用与 LiteLLM 相同的 `litellm` 导入和供应商适配代码；没有运行独立 LiteLLM 网关，也没有安装其企业服务。

完整供应商标识从安装版本的 `litellm.provider_list` 动态读取，当前为 **173 项**，不局限于界面的快捷配置。完整目录包含部分非对话服务，本功能需要能输出文本的对话模型。上游支持范围、模型权限和额外依赖以 [供应商文档](https://docs.litellm.ai/docs/providers) 为准，不代表每一项都能仅用 API Key 完成认证。

常用方式：

| 接入方式 | 填写方法 |
| --- | --- |
| LiteLLM 原生供应商 | 供应商标识如 `deepseek`、`anthropic`、`gemini`、`openrouter` 等，模型 ID 按其控制台或 LiteLLM 文档填写；默认接口可留空 |
| OpenAI 兼容接口 | 供应商标识填 `openai`，填写服务的完整基础地址（例如包含 `/v1` 或供应商要求的兼容路径）和模型 ID |
| 阿里云百炼、Moonshot/Kimi 等兼容接口 | 可用快捷配置填入常见基础地址；区域或服务类型不同时请使用控制台给出的实际地址 |
| 本地 Ollama / LM Studio | 快捷配置为其 OpenAI 兼容基础地址；本地服务需另行启动，模型 ID 必须实际存在；无认证时可不填 API Key |
| Azure、Bedrock、Vertex 等高级云平台 | 按 LiteLLM 文档填写区域、API 版本、项目和认证参数；部分适配器需要额外官方可选依赖，安装到本项目 `.venv/` 后使用 |

「供应商参数 JSON」原样传给 LiteLLM，例如 `api_version`、`aws_region_name`、`vertex_project`、`vertex_location`、额外凭据或 `extra_headers`。参数整体按敏感信息保存，不回显；修改时需重新填写完整对象。应用保留模型、提示词、回调、目标地址、重试和超时等控制项，不能通过这个 JSON 覆盖。请勿添加上游日志回调或远程调试配置。

模型输入框提供 SDK 随包模型目录参考，也能手填新模型 ID。这个目录不是供应商的实时可用列表，也不表示你的账号具有相应模型权限。

## 数据与凭据

- API Key 和额外认证参数保存在本项目 `data/ai/providers.json`，文件权限 `0600`、目录权限 `0700`。这是本地明文配置，依靠当前用户的文件访问权限保护，不是密钥链或加密保险库。
- 浏览器只收到连接名称、供应商、模型、地址及「是否保存密钥」状态，不会读回密钥或高级参数。输入框留空沿用原值；可明确清除。更换供应商或接口地址时，需要重新填写或清除旧凭据。
- 题集导出不包含 API Key 或供应商认证参数。生成的题集记录供应商、模型和来源课程；分析保留同类来源信息。
- 点击出题会发送本课校对文本、画面文字、待核对分歧和出题要求；点击分析会发送课程快照、原题、作答、参考答案、判分及分析要求。**不发送视频文件。** 云端请求可能产生供应商费用，具体以其账单为准。
- 语音识别继续本地运行。快、中、慢档影响本地转写与复核；不会控制云端服务或独立 Ollama / LM Studio 进程的速度及发热。
- SDK 使用本地随包目录，关闭本项目使用的额外日志和默认目录刷新；只在明确点击调用/测试时请求所配置服务。应用不配置第三方观测回调。

## 等待、取消和错误

调用作为后台任务保存到 `data/ai/tasks/`，刷新后能恢复状态。最多同时两个模型请求，同一课程/题集的同类进行中任务会复用，避免重复点击发起相同任务。

不会自动切换备用供应商，也不会自动重试付费请求。取消会终止本地等待和请求；供应商可能已经处理部分内容，不能保证取消计费。重启应用会把未完成请求标记为中断，不会自动重发。

模型输出达到上限、为空或不符合题集协议时，不会导入半成品；原始输出留在任务中，可查看、修正后手动导入。输出预算、题数、上下文长度和超时可按实际模型调整，应用不自动截断学习资料。

如果生成分析期间作答或反馈已变更，AI 结果会保留，但不会覆盖新内容。正常保存 AI 分析时，旧反馈保留在题集完整 JSON 的 `analysis_history` 中；最多保存 20 份历史。历史不在默认答题接口回显，避免夹带旧答案。

## 验证

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -q
# 真正的 LiteLLM SDK 与本机模拟 HTTP 供应商联调，不使用真实密钥、禁止外部网络
.venv/bin/python tests/check_ai_integration.py
```

当前已通过 60 项检查，并用真实 SDK 完成「测试连接 → 生成题集 → 答题判分 → 生成并保存分析」的本机 HTTP 联调及界面操作。供应商账号、权限和付费模型未用真实密钥逐家验证；配置自己的连接后可先测试，再用课程调用。
