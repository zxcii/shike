# 快、中、慢三档：只调度，不降低识别配置

界面的「运行速度」对转写、独立复核、画面识别生效，可以在任务运行中修改，设置保存在本项目 `data/performance.json`。没有配置或配置损坏时默认使用慢档。

| 档位 | 调度目标 | 使用取向 |
| --- | --- | --- |
| 快 | 连续计算，正常时不主动插入冷却 | 优先完成任务，发热相对更高 |
| 中 | 约 35% 工作占空比，其余时间冷却 | 较低持续负载 |
| 慢 | 约 5% 工作占空比，计算后约休息工作时间的 19 倍 | 低热优先，耗时明显增加 |

这些百分比是应用的计算/冷却调度目标，不是 macOS 活动监视器里的 CPU/GPU 占用承诺，也不是精确温度或功率指标。模型加载、文件读取、单次不可中断 GPU 运算仍可能出现短暂负载。机器温度还受其他程序、充电、室温、散热条件影响，软件无法保证机身温度的绝对上限。

## 识别配置保持相同

三档保持相同的模型文件、MiMo 量化格式、Whisper FP16、音频数据、片段边界、提示词、解码参数和复核流程。不换小模型，不额外降低精度，不跳过片段、画面抽样或复核，不减少输出 token 上限。

画面识别仍使用同一套 OCR 参数和每秒抽样策略。降低的仅是运行负载和工作频率；同样的任务会花更长时间。

## 如何冷却

- GPU：在 MLX 计算检查点和 MiMo 逐 token 采样处等待实际计算结束，并同步 GPU 队列后再暂停。Whisper 的异步计算在中、慢档完成求值后才进入冷却，避免 CPU 睡眠时 GPU 仍在后台连续计算。
- CPU 轻量模式：独立模型子进程使用一个推理线程，调度器以运行/暂停的方式限制原生 C++ 计算，避免只在 Python 片段边界暂停而让 CPU 长时间满载。
- 画面识别：降低解码线程数，在抽样处理检查点按档位插入冷却；不降低画面抽样数量或识别质量。
- 热压力：读取 macOS 公共 `NSProcessInfo.thermalState`。中、慢档在系统报告 fair 或更高时暂停等待恢复；快档在 serious/critical 时也会等待。该状态不是摄氏温度。
- 系统热状态不可读取时，仍按固定占空比冷却，不会默认为满速。
- 运行中改档位会在下一个计算检查点生效；正在冷却时约每 0.25 秒检查新设置。切回更快档位可中止尚未完成的额外冷却，但系统热压力过高时仍会等待降温。
- 只设置应用自身进程的低优先级与数值库线程限制，不修改系统电源设置、风扇或系统 GPU 保护阈值。

## 界面与记录

任务进行时会显示正在计算、冷却倒计时或等待系统降温。模型运行指标另外保存实际工作与冷却秒数，便于核对节流是否生效。

建议先保持默认慢档。在长课程上，等待时间可能比快档增加很多；这正是保持识别配置并降低平均负载的代价。

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
node --check static/app.js
# 本机真实 MiMo 和 Whisper 三档输出对比；使用独立临时档位文件，不改用户设置

```

三档真实输出对比结果保存在 `docs/speed-validation.json`。测试通过只能证明该固定样本输出一致，不保证所有输入在不同计算调度下逐位相同；本实现没有主动降低识别配置来换取速度。

### 本机真实对照结果

在 M4 / 16 GiB 上，用同一段 4 秒音频分别运行快、中、慢三档的 MiMo 主识别和 Whisper Large-v3 复核。两个模型各自的三档输出文字完全一致。

| 慢档模型 | 实测工作时间 | 实测主动冷却时间 |
| --- | --- | --- |
| MiMo 4-bit | 6.930 秒 | 131.504 秒 |
| Whisper Large-v3 | 4.625 秒 | 87.758 秒 |

两者实测调度占比约 5%。这不是机身温度测量；包含 CPU 准备、I/O 与同步的应用工作时间口径，也不等同于精确 GPU 利用率。
